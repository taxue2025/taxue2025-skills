# JD 解码四步法

> 解读 JD 的深层信息，让简历和面试准备对准「最合适的那个人」。

## JD 的两层信息

**表层**（写出来的）：职责、要求、加分项
**深层**（没写出来的）：为什么这个岗位存在、这个团队在哪个阶段、招的人要解决什么问题

只看表层，你准备的是「合格」。读懂深层，你准备的是「最合适的那个人」。

## 第一步：判断岗位成熟度

| JD 特征 | 团队阶段 | 隐含期望 |
|---------|---------|---------|
| 职责模糊、「等你来定义」 | 从零到一 | 要能白手起家、自驱 |
| 职责精细、流程成熟 | 规模化运营 | 要执行力、不折腾 |
| 既要A又要B又要C | 人手不足 | 要「多面手」，可能资源少 |
| 要求极高但薪资模糊 | 不确定出多少 | 先摸底，再谈 |

## 第二步：提取真实要求

把 JD 要求分三类：
- **硬门槛**（不满足直接被刷）：学历、证书、年限、特定行业经验
- **核心要求**（写在前三条的）：这是真正考核的重点
- **加分项**（「优先考虑」）：有则好，没有不是问题

## 第三步：识别隐含要求（比文字更重要）

- 「有 XX 行业经验」→ 他们不想培训，要即战力
- 「能承受压力」→ 这个岗位压力确实大，可能经常加班或背 KPI
- 「良好的沟通能力」在技术岗出现 → 要和非技术方大量协作
- 「有创业/初创公司经验」→ 环境不稳定，要适应模糊
- 「vibe coding」「能自己写代码」→ 期望你能自己动手验证想法。面试带上你做过的东西
- 「对XX有品味/判断力」→ 你的判断标准比使用清单更重要。准备好说出哪个产品好、**为什么**好

## 第四步：判断匹配度

```
硬门槛全满足？   是 → 可投  否 → 放弃（不要赌）
核心要求满足≥70%？  是 → 可投  否 → 优化简历或放弃
加分项满足≥1个？    是 → 有竞争力  否 → 仍可投，但要补充其他亮点
```

## 前沿技术岗特别解码（A0+）

AI/大模型/Agent 岗位四问：
1. **岗位为何存在**：是核心业务还是蹭热点？
2. **品味要求**：JD 里「有品味/判断力」到底要什么？
3. **动手能力信号**：「vibe coding」「能自己写」→ 要能自己验证想法
4. **3 年后岗位是否还存在**：判断岗位的长期性
