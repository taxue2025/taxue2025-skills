# taxue-learn：踏雪学习方法论

> **一句话**：学习不是接收信息，是改变行为。

---

## 快速上手

**典型流程**：
```
用户：我想学习价值投资
    ↓
收件箱：找到《聪明的投资者》这一本经典
    ↓
知识原子：提取3个核心概念（安全边际/市场先生/能力圈）
    ↓
交互内化：苏格拉底追问 + 费曼复述 + 闯关测验
    ↓
系统输出：写成文章/做成Skill/教给别人
    ↓
归档迭代：持续优化知识体系
```

---

## 四步内化法

### 第一步：收件箱原则（输入）

**德鲁克：效能 > 效率**

不要追求「看了多少」，要追求「留住什么」。

**操作**：
- 所有信息先进「收件箱」
- 3秒判断：**噪音删除** / **信号归档** / **模糊留置**
- 每周清理，不让积压超过7天

**关键问题**：这个素材什么时候用？对谁有用？

---

### 第二步：知识原子（整理）

**西蒙：有限理性**

不要存原文，要存「知识原子」——最小可复用单元。

**原子结构**：
```
核心观点（1句话）
关键细节（3-5条）
适用场景（什么时候用）
个人理解（和我的经验关联）
```

**原则**：每个原子必须回答「什么时候用」，否则就是垃圾。

---

### 第三步：交互内化（掌握）

**费曼：如果你不能简单解释它，你就没真正理解它**

被动阅读留存率 10%，主动输出留存率 90%。

| 方法 | 适用场景 | 操作 |
|------|---------|------|
| **苏格拉底追问** | 有个「听起来对」的观点 | 提反例，逼到边界，澄清定义 |
| **案例分析** | 抽象概念需要落地 | 真实场景，问「你会怎么做」 |
| **费曼复述** | 验证是否真懂 | 不用术语，讲给外行听 |
| **闯关测验** | 快速验收 | 判断→选择→应用→反例 |

**内化检验**：
- [ ] 能不用术语解释清楚
- [ ] 能举3个不同领域的例子
- [ ] 能说出「什么时候不适用」

**图尔明验证——真懂的质量门槛**

内化结束前，确认你能完整填写：

```
主张：我认为 {核心观点X}
数据：因为 {具体可观察的证据或案例Y}
保证：Y 能支撑 X，是因为底层逻辑 {Z}
限定：在 {具体反例或条件} 下不成立
反向：不这么做会发生 {可观察的具体后果}
```

**判断标准**：如果写不出「保证」（底层逻辑），说明还没真懂——只是记住了结论，没有理解推导路径。继续追问：「为什么 Y 能推出 X？」

**认知位移记录**

学习结束时追踪自己的思维变化：

```
入场立场：「我原来以为……」
现在立场：「现在我认为……」
改变来源：「是 {哪个论点/案例/追问} 让我改变的」
```

没有认知位移 = 只是信息接收，不是内化。好的内化至少让一个原有假设站不住脚。

---

### 第四步：系统输出（固化）

**踏雪：能固化，不复述**

遇到重复问题，建系统。一次建设，长期受益。

**六步编译法**：
1. **目的**：解决什么问题？
2. **标准**：什么叫「做好了」？
3. **边界**：什么时候不用？
4. **界面**：怎么调用？
5. **验收**：3个场景测试
6. **迭代**：用起来，再改

## 内化流图谱

```
信息输入
    ↓
收件箱筛选（噪音删除 / 信号归档）
    ↓
知识原子（最小可复用单元）
    ↓
交互内化（追问 / 案例 / 费曼 / 测验）
    ↓
图尔明验证（主张→数据→保证→限定→反向）← 质量门槛
    ↓
认知位移记录（入场立场 → 现在立场 → 改变来源）
    ↓
方法论提炼（从重复中提取框架）
    ↓
系统输出（Skill / 文章 / 产品）
    ↓
归档迭代（持续优化）
```

## 常见问题

| 问题 | 答案 |
|------|------|
| 信息太多学不过来？ | 用「3源法则」：只学最经典的3个源头 |
| 学完就忘？ | 输出倒逼输入。教给别人，卡住的地方就是没真懂 |
| 学了不知道怎么用？ | 每个知识原子必须回答：什么时候用？对谁有用？ |
| 怎么判断进步了？ | 看输出：能写的卡片数量、文章深度、解决实际问题的能力 |

根据你的当前阶段选择起点：

## 原则库

1. **先筛选，再处理**：用3秒判断，不让噪音进入大脑
2. **输出倒逼输入**：写不出来，说明没真懂
3. **能固化，不复述**：一次建设，长期受益
4. **每个原子必须有场景**：没有适用场景的素材是垃圾
