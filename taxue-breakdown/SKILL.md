# taxue-breakdown：拆任务

> 拆到可执行，才算拆完。

你的任务：把一个复杂目标拆成能动手的步骤。不做战略建议，不判断方向对不对——只做结构化分解。

拆的底线：每个子任务必须有个「15 分钟内能动手」的最小行动。第一步还需要「准备一下」才能开始，说明没拆完。第一步要明天才能做，那是列愿望清单，不是拆任务。

拆完如果发现重复出现的结构——同样的依赖、同样的顺序、同样的卡点——标出来。下次可以直接复用，不用从头拆。

---

## 先看清楚再拆

**第一步：确认目标。** 问一句「要完成什么？有截止时间吗？」目标模糊就追问——做什么形式？给谁看？发哪里？目标太大就缩到当前阶段能定义的状态。目标清楚了，再往下走。

**第二步：找依赖。** 每件事都有前置条件。信息够不够？工具/预算/人到位了没？需要谁先拍板？技能缺不缺？每个依赖只标三种状态：已有、需获取、需决策。

**第三步：判断结构类型。** 别上来就列清单。先看这件事是什么形状——线性过程就按顺序拆里程碑。并行协调就先拆依赖关系，再分头行动。探索型就先收集信息，下一步干什么取决于收集到什么。

---

## 开拆

用四层结构：目标 → 里程碑 → 子任务 → 最小行动。

```
目标：{一句话}
截止：{时间}

里程碑 1：本周能完成的
  [ ] 子任务：{具体动作}
       最小行动：{15 分钟内能开始}
  ...

里程碑 2：下周
  ...

里程碑 3：截止前
  ...
```

每个里程碑 2-5 个子任务，多了说明没拆透。每个子任务必须带最小行动。碰到纯执行的标 `[快]`，判断密集的标 `[慢]`（慢的有积累价值）。有前置 block 就标 `[block: 原因]`。

拆完了问一句：「哪些下次再做会更容易？哪些每次都得从头来？」——这是德鲁克的老问题。能固化的，标记给 `taxue-build`。

## 反模式声明（常见失败）

### 失败 1：拆到「准备一下」就停了
子任务的第一步是「准备一下资料」「先了解一下背景」——这不算拆解，这是拖延。
**纠正**：每个子任务必须有「15 分钟内能开始」的最小行动。如果第一步还需要「准备」，说明拆得不够细，继续拆。

### 失败 2：所有子任务都是「线性过程」
不管问题类型，一律按顺序拆里程碑。但用户的实际问题可能是「探索型」的——需要先获取信息才能决定方向。
**纠正**：先判断结构类型（线性/并行/探索），再动手拆解。探索型的第一步不是「做」，是「获取信息」。

### 失败 3：拆完不问「哪些可固化」
拆解完成后直接给方案，没有检查「哪些任务结构是重复出现的」。
**纠正**：拆解完成后必须执行德鲁克追问——「哪些是下次再做会更容易的？哪些是每次都要从头来的？」发现可固化的结构，标记为 `taxue-build` 候选。

## 验证方式

做完后问自己几件事。拆出来的最小动作，是不是今天就能开始？有没有标清楚哪步必须先做、哪步可以并行？时间估算是不是具体的——不是「尽快」，是「大约需要两天」。

## DO NOT

- 从零创建新 skill → `skill-creator`
- 方向还不清楚 → `taxue-solve`（先解决方向问题再拆解）
- 需要战略建议/方向判断 → `taxue-solve`（breakdown 只执行拆解，不判断方向）
