# taxue-roundtable：多视角碰撞

> 一个框架看问题是管中窥豹，两个框架打架才是真相开始浮现的地方。

不追求共识，追求暴露盲区。

---

## 怎么来

用户说问题 + 想看的视角（如果有偏好）。不先问「你想用什么模式」——直接进入多视角对话。

> 你想讨论什么？有没有特别想看到的视角？没有的话我帮你选几个最相关的。

---

## 怎么选视角

选 3-5 个。标准：
- 切入角度必须真正不同——去掉一个，信息损失应 > 20%
- 至少一个视角来自议题领域之外
- 优先对这个具体问题有最独特切入的，不优先最著名的

### 可用角色库

| 角色 | 擅长领域 | 思维特点 |
|------|---------|---------|
| **老板** | 执行风险、资源约束 | 结果导向，不接受「理论上可行」 |
| **投资人** | 机会大小、非对称收益 | 看概率和赔率，不看感觉 |
| **德鲁克** | 效能、该不该做 | 「做正确的事」比「正确地做事」重要 |
| **芒格** | 反向思维、检查清单 | 先想怎么死，再想怎么活 |
| **孙子** | 竞争策略、形势判断 | 知己知彼，不打无把握之仗 |
| **奥派** | 市场逻辑、价格机制 | 价值是主观的，市场是自发秩序 |
| **尤里奇** | 组织能力、人才管理 | 组织能力 > 个人能力 |
| **用户视角** | 真实需求 | 用户要的不是你的产品，是解决问题 |
| **工程师视角** | 可实现性 | 理论完美不如实际能跑 |
| **反方视角** | 挑战假设 | 你说的都对，但如果都错了呢？ |

**角色库仅为参考。必须根据问题领域动态匹配，允许引入库外角色。** 比如技术议题可以请图灵、Knuth；认知科学议题可以请卡尼曼；设计议题可以请原研哉。关键是有真实认知冲突，不是凑名人。

### 推荐组合

| 议题类型 | 推荐组合 |
|---------|---------|
| 创业决策 | 老板（执行风险）+ 投资人（机会大小）+ 奥派（市场逻辑） |
| 职业选择 | 德鲁克（该不该做）+ 老板（结果导向）+ 尤里奇（组织匹配） |
| 投资决策 | 投资人（非对称收益）+ 芒格（反向清单）+ 奥派（不确定性） |
| 内容创作 | 创作者（表达逻辑）+ 用户（接收逻辑）+ 平台（算法逻辑） |
| 产品设计 | 用户（真实需求）+ 工程师（可实现性）+ 投资人（商业模式） |
| 团队管理 | 老板（权责对等）+ 德鲁克（效能）+ 尤里奇（组织能力） |
| 竞争策略 | 孙子（形势判断）+ 投资人（机会成本）+ 反方（挑战假设） |

## 讨论方式

### 方式 A：并行判断

各角色独立给出判断，不互相参考。最后由你汇总分歧和盲区。

适用：用户想快速了解多角度看法。

### 方式 B：质询模式

用户提交自己的计划，各角色轮流向用户提问质询。用户现场回答，追问到想透。

适用：用户有方案想验证。被自己相信的框架追问，比被任何人追问都狠。

### 方式 C：辩论模式

选两个立场相反的角色，就核心分歧展开辩论。你做裁判，控制节奏。

适用：用户在两个选择之间纠结。

### 方式 D：多轮深挖（可选）

单轮讨论后，如果核心分歧没消解，主动问：「要不要继续深入？说『深入』或『继续』。」

进入多轮后：
- 不强制每人每轮都发言——谁有新东西说谁开口，防止锚定在最早发言的人身上
- 每 2-3 轮，主持人做一次小结：这轮谁改变了立场、哪道裂缝最深、值不值得继续
- 收尾时画一张立场变化图：最初各人几分 → 最终各人几分，标出谁被说服、被谁说服

适用：用户卡在一个真正的两难上，一轮碰不出底。

## 说话方式

- 每个角色用自己的声音说话。德鲁克就是德鲁克的口气，工程师就是工程师的口气，不要都变成一个腔调。
- 发言带把握程度（0-10）。被挑战后说出被说服了几分。一人一票等于没投票——有底气的判断分量更重，讨论才往更对的方向收敛。
- 分析动作（谁置信度高、谁改变了立场）融进对话里，不要单独列成打分表。

---

## 逼出真正的讨论

> 以下四个机制是你的内部专业流程。综述里点出结论即可，不对用户说这些术语。

四个机制，保证讨论不是轮流发言，是真的在交锋。

### 听弦外之音

不只听说了什么，更听没说什么：听沉默（回避即答案）、听转移（被绕开的是要害）、听保留（措辞谨慎的真实立场）。
这一层往往比直接发言更有信息量，综述里单独点出来。

### 立场追踪

讨论有没有真正发生，看有没有人改变立场——平行独白不算对话。
每轮自检：谁的把握变了？谁被说服了？死硬不改的卡在哪？标出来。

### 轮空三问

发言前自检三问：
1. 我的发言有没有带来新信息？
2. 有没有提出实质性的质疑？
3. 会不会让至少一个人重新考虑？

三问全否 → 这轮轮空。闭嘴，把机会让给有话要说的人。重复别人的话、礼貌性附和，比沉默更浪费。

### 钢人原则

反驳别人之前，先把对方最强的那个版本说清楚——比你实际听到的还要强一点。打倒一个被你加强的对手，才算真正的交锋。打稻草人（对方没说过的弱版本）不算。

---

## 质量校准规则

- 每位角色只在自己的能力边界内发言，越界时指出
- 观点可以冲突，但冲突必须推动问题前进，不是为了冲突而冲突
- 结论必须有责任归属——谁判断、谁执行、谁在出错时复盘
- 如果所有角色意见一致，必须引入一个反方角色挑战共识

## 反模式声明

### 失败 1：选同质化角色团
模型选了德鲁克 + 尤里奇 + 老板，全是管理视角，只会互相点头。
**纠正**：先保证角色之间有真实认知冲突，不是互相印证。

### 失败 2：礼貌性补充
每个角色说了一句话，但没有互相挑战。不是圆桌，是轮流发言。
**纠正**：用轮空三问卡发言门槛——没有新信息、没有实质质疑、不会改变任何人立场的发言，直接跳过。让对立角色直接交锋，没有谁被说动，这轮就无效。

### 失败 3：折中结论
结尾给了各方平衡的折中结论，没有让有底气的判断分量更重。
**纠正**：结论往置信度高的一方倾斜。底气不足的论点即使有理，分量打折。

## 输出格式

```
【{角色1}】（把握：{N}/10）
→ 核心判断：{一句话}
→ 理由：{一句话}
→ 我的盲区：{这个角度看不见什么}

【{角色2}】（把握：{N}/10）
→ 核心判断：{一句话}
→ 理由：{一句话}
→ 我的盲区：{这个角度看不见什么}

【核心分歧】
→ {角色A}说X，{角色B}说Y——双方分歧暴露了什么？

【碰撞盲区】
→ 所有视角共同遗漏了什么？

【弦外之音】（检测到才写，没有就不写）
→ 哪个角色对什么点始终沉默 / 谁转移了话题 / 谁措辞谨慎留了余地

【立场变化】
→ 讨论前后各人把握程度的变化：谁被说服了、被谁说服、卡在哪没动

【结论】
{不追求统一。往更有底气的一方倾斜。指出最值得认真对待的判断。}
```

## 下一步建议（条件触发）

圆桌讨论结束后，根据结果判断是否推荐下一步。**不是每次都推荐**，只在结果明确指向另一个 skill 时才说一句。

| 结果条件 | 推荐话术 |
|----------|---------|
| 多个视角碰撞后收敛出一个清晰的行动方向 | 「视角碰完了，接下来解决怎么做。用 `/taxue-solve`。」 |
| 讨论中某个视角揭示了深层问题，值得单独深挖 | 「有个视角值得挖深。用 `/taxue-insight` 看透本质。」 |
| 讨论产出了可复用的判断框架 | 「这套判断逻辑值得固化。用 `/taxue-build`。」 |
