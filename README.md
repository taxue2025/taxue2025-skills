## 从「工具」到「工作流」

旧模式的问题：

你打开工具箱，里面有 20 个工具。你盯着它们发呆，不知道用哪个。

用了一个，做完了，不知道下一步该干嘛。

每个工具都要单独学习，成本太高。

新系统的解法：

**统一入口** (`/taxue`) —— 你不用选，系统帮你判断。

**方法论显性化** (`taxue-learn`) —— 不是告诉你「要好好学习」，是展示「我怎么内化知识」。

**决策质量升级** (`taxue-roundtable`) —— 四位大师同时给你建议，不是一个人拍脑袋。

**经验资产化** (`taxue-build`) —— 你解决过的问题，变成可复用的 Skill，下次直接调用。

## 为什么需要 Skill

普通 AI 对话的问题：

每次都要重复交代背景。

输出质量忽高忽低，看运气。

复杂任务需要你自己拆解，AI 只会执行。

你不知道 AI 能做什么，只能碰运气提问。

**Skill 解决的核心问题**：把「知道怎么做」编码成「自动触发、标准输出」的能力单元。

## 设计理念

### 1. 德鲁克有效性原则

> 「效率是把事情做对，有效性是做对的事情。」

每个 Skill 创建前必须通过三问：

这重要吗？不做会影响结果吗？

Agent 没有 Skill 能做吗？基线测试验证价值。

会被使用 5 次以上吗？复用频率门槛。

### 2. 精准触发机制

不是让用户选择 Skill，而是让 Skill 识别场景：

```
"帮我看简历" → 自动激活 career-resume-diagnosis
"想离职" → 自动激活 career-exit-management
"设计一个 Skill" → 自动激活 skill-designer
```

### 3. 渐进式能力披露

每个 Skill 三层结构：

YAML 头部 —— Agent 快速识别是否该用。

正文 —— 执行时的标准流程。

参考文档 —— 深度原理和边界情况。

## 深度使用

### 圆桌讨论

输入 `/roundtable` 或「开圆桌讨论」，启动四贤并行问道：

德鲁克：这是正确的事吗？

芒格：我们可能在哪里欺骗自己？

孙子：胜负在开战前决定了吗？

Ulrich：综合建议与下游行动。

### 经验固化

输入 `/build` 或「写个 skill」，六步编译法把你的解法变成资产：

目的：解决什么问题？

标准：什么叫做好了？

边界：什么时候不用？

界面：用户怎么调用？

验收：3个真实场景测试。

迭代：根据反馈优化。
