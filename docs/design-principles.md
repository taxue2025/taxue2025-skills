# Taxue Skills 设计原则

## 核心原则

1. **先澄清，后解决**：80% 的纠结是因为问题本身有问题。先花 2 分钟验证问题，省 2 个月走弯路。
2. **够用就好，不要完美**：追求当前够用的方案，不追求完美方案。推动行动大于完美分析。
3. **推动行动，不给建议**：不说「你可以考虑」，说「第一步做 X」。
4. **能固化，不复述**：重复的问题写成 Skill，一次建设长期受益。

## 哲学锚点

| 哲学家 | 映射 |
|--------|------|
| 亚里士多德「第一性原理」 | 剥离表象，找到底层机制。每个 Skill 都要能回答「本质是什么」 |
| 杜威「实用主义」 | 不能推动行动的思考都是空转。拆解到 15 分钟能开始才算拆完 |
| 德鲁克「有效性」 | 对谁有价值？做完后外部世界发生了什么变化？ |
| 阿德勒「目的论」 | 情绪在保护你避开什么？你真正害怕面对的是什么？ |
| 芒格「格栅思维」 | 单一视角必然盲视。用多个学科交叉验证 |
| 维特根斯坦「语言审查」 | 说不清的概念等于伪概念。拆到可操作才算真懂 |

## Skill 设计规范

### 必备要素
- **description**：含触发词 + DO NOT use when 边界
- **核心公理/原则**：方法论锚点
- **Phase 流程**：可执行的步骤
- **下游协作**：条件触发路由
- **语言规则**：中文遵循《中文文案排版指北》

### 尺寸约束
- SKILL.md 建议 50-250 行
- 超过 250 行考虑拆分
- 低于 30 行考虑合并

### 触发词设计
- 斜杠命令 + 自然语言关键词 + 场景描述，三级覆盖
- 相邻 skill 触发词必须互斥
- DO NOT use when 覆盖所有不应触发的场景
