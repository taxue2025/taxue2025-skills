# Taxue Skills 设计原理

> 每个 Skill 的设计不是拍脑袋——背后有一套可追溯的哲学。

---

## 哲学锚点体系

### 亚里士多德「第一性原理」

**在 Taxue 中的映射**：

每个 Skill 必须能回答「这个问题的本质是什么」。当用户用形容词和情绪描述问题、没有触及基本事实时，触发第一性原理追问。

**使用场景**：
- `taxue-insight`：剥离表象到底层机制
- `taxue-solve`：验证问题本身站得住
- `taxue-calm`：剥掉感受，剩下的事实是什么

### 杜威「实用主义」

**在 Taxue 中的映射**：

不能推动行动的思考都是空转。拆解到「15 分钟能开始」才算拆完。

**使用场景**：
- `taxue-breakdown`：拆到可执行才算完
- `taxue-solve`：推动行动大于完美分析
- `taxue-learn`：不是先学再做，是在做中学

### 德鲁克「有效性」

**在 Taxue 中的映射**：

效率是把事情做对，有效性是做对的事情。每个输出前必须问：谁受益？不做会怎样？

**使用场景**：
- `taxue-content`：消费者是谁，看完会做什么
- `taxue-insight`：对使用者有什么价值
- `taxue-business`：这个生意存在的理由是什么
- `taxue-save`：存档越具体，恢复越省力

### 阿德勒「目的论」

**在 Taxue 中的映射**：

情绪不是原因，是目的。不是「因为我焦虑所以做不了」，而是「焦虑让我不用面对那个真正让我害怕的事」。

**使用场景**：
- `taxue-calm`：这个情绪在保护你避开什么
- `taxue-relate`：真正害怕面对的是什么

### 芒格「格栅思维」

**在 Taxue 中的映射**：

单一视角必然盲视。多学科思维模型交叉验证，才能接近真相。

**使用场景**：
- `taxue-roundtable`：四贤并行，覆盖不同视角
- `taxue-insight`：用多个领域模型验证

### 维特根斯坦「语言审查」

**在 Taxue 中的映射**：

说不清的概念等于伪概念。「商业模式」「底层逻辑」「核心竞争力」——这些词能说清楚是什么意思吗？

**使用场景**：
- `taxue-solve`：消解漏斗追问「你说的 XX 具体指什么」
- `taxue-business`：定义每个商业术语

## 路由哲学

### 三层路由

```
第一层：Taxue 体系内解决
→ 用户输入自动匹配到对应子 Skill
→ 匹配失败走第二层

第二层：深度场景/专项
→ 情绪/关系/表达/商业/职业
→ 匹配失败走第三层

第三层：超出能力
→ 2 句话告诉用户自己能做什么
→ 让用户选择，不强行路由
```

### 路由原则

1. **信号词优先于关键词**：用户说「很焦虑」→ `taxue-calm`，不是因为「焦虑」这个词，是因为这个词指向情绪解码场景
2. **匹配失败不猜测**：不强行路由到不相关的 Skill，直接展示可选列表
3. **不留用户空转**：路由后一定给出明确结果——要么进入对应 Skill，要么给出 2 句话的能力列表

## 输出哲学

每个 Skill 的输出需通过「三可检查」：

| 检查 | 含义 | 标准 |
|------|------|------|
| ✅ 可执行 | 用户能立即开始做 | 第一步不需要「准备一下」 |
| ✅ 可带走 | 用完能留下东西 | 模板、话术、清单、框架 |
| ✅ 可验证 | 做完能知道有没有效果 | 有明确的完成标准 |

---

## 状态设计

复杂的问题不是一次会话能解决的。状态管理三模式：

```
--progress：解决问题的路上
--restore：接着上次继续
--decision：记录关键决策
```

### 设计原则

1. **存档自动提示**：每个子 skill 执行到节点时，主动问「要不要存一下？」
2. **恢复零成本**：一句「继续上次」就能恢复，不需要回忆背景
3. **决策不美化**：记下当时的假设、理由、预期，而不是结果


## Skill 质量门禁

每个 Skill 创建或更新时必须通过：

- [ ] 是否只解决一个主要矛盾？
- [ ] 输出是否直接可用？
- [ ] 用户今天能不能开始做？
- [ ] 是否留了余地让用户参与？
- [ ] 哲学锚点是否明确？
- [ ] 路由信号词是否完整？
- [ ] 边界条件是否清晰？
